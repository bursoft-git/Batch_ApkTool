BATCH APKTOOL 3.9.2 by BurSoft

BATCH APKTOOL - это мощная оболочка, объединяющая несколько инструментов для работы с файлами APK.
Позволяет пакетно декомпилировать, изменять ресурсы и smali-код, рекомпилировать, подписывать, выравнивать (zipalign) APK, ZIP, JAR-файлы.
Дополнительно есть возможность подключения плагинов, просмотра исходного Java кода APK, JAR и DEX-файлов, работы с устройством через ADB, и др.

Подготовка к работе:
Распакуйте архив. В пути к утилите и в именах обрабатываемых файлов избегайте длинных путей, использования спецсимволов (восклицательный знак !, проценты %, карет ^ и др.) и русских букв. Лучше всего использовать короткий путь вида d:\BatchApkTool\

1.   Декомпиляция и рекомпиляция:
1.1  Поместите файлы для обработки в папку _INPUT_APK.
1.2  Если вы разбираете системные файлы из прошивки, поместите все APK-файлы из папки system/framework этой прошивки в папку _framework утилиты; в противном случае оставьте папку _framework пустой.
1.3  Выберите пункт меню [1](2) или [01](02). В папке _INPUT_APK появятся разобранные приложения.
1.4  Внесите необходимые изменения.
1.5  Если вы разбираете системные файлы, ВЫКЛючите опцию [88] - это сохранит оригинальную подпись системных APK. Если опция [88] ВКЛючена, во время рекомпиляции приложение будет подписано ключем, выбранным в пункте [89].
1.6  Выберите пункт [3] или [03]. Перепакованные, подписанные (если включена соответствующая опция) и выравненные APK будут находиться в папке _OUT_APK.
1.7  Пункты [05], [06], [07] и [08] предназначены для декомпиляции и рекомпиляции APK или JAR файлов при помощи baksmali-smali. Декомпилируется только smali-код.
Для этого поместите APК файлы в папку _INPUT_APK (JAR файлы в папку _INPUT_JAR), выберите версию smali, укажите API level, декомпилируйте, внесите необходимые изменения и рекомпилируйте.
Перепакованные, подписанные (если включена соответствующая опция) и выравненные файлы будут находиться в папках _OUT_APK (_OUT_JAR).

2.   Инструменты:
2.1  Пункт [4] позволяет подписывать APK, ZIP, JAR файлы. Версия подписи будет выбрана автоматически, в зависимости от версии SDK приложения. Поместите файлы для подписи в папку _INPUT_APK, подписанные и выравненные файлы будут находиться в папке _OUT_APK.
2.2  Пункт [5] позволяет выравнивать (zipalign) APK-файлы. Поместите файлы для выравнивания в папку _INPUT_APK, выравненные файлы будут находиться в папке _OUT_APK.
2.3  Пункт [6] позволяет просмотреть исходный Java код APK, JAR и DEX файлов, а также ресурсы APK-файлов.
2.4  Пункт [7] позволяет запускать плагины. Если вы хотите создать собственный плагин, см. примеры в папке bin\plugins.
На форуме 4PDA (https://4pda.to/forum/index.php?showtopic=557858) доступны плагины для клонирования апк, оптимизации размера графических файлов, патчинга защиты по подписи, и т.д.
2.5  Пункт [04] позволяет объединить разделённые APK (apks, apkm, xapk) в один APK.
2.6  Пункты в категории ОБСЛУЖИВАНИЕ позволяют очистить соответствующие папки утилиты.

3.   ADB:
Позволяет работать с устройством через Android Debug Bridge. Для корректной работы ADB необходимо:
На ПК:
- Установить драйвер ADB для вашего устройства.
На устройстве:
- Включить настройки для разработчиков. Для этого идем в Настройки -> О телефоне, и несколько раз тапаем на пункт Номер сборки.
- В Настройках - Для разработчиков включаем Отладку по USB, Установку через USB, Отладку по USB (настройки безопасности).
- Для беспроводной отладки включите отладку по Wi-Fi и откройте Подключение с помощью кода подключения.
3.1  Пункт [10] - с него следует начинать работу с ADB.
Отображает список устройств для подключения. Устройства, готовые для подключения, помечены как [device].
Беспроводные устройства, доступные для спаривания, помечены ***. После спаривания и ввода кода подключения, они станут готовы для подключения.
Устройства, которые не отображаются в списке, можно подключить, введя IP адрес вручную.
ВНИМАНИЕ. При поиске и подключении на устройстве появится всплывающее окно, в нем нужно поставить галку "Всегда разрешать отладку с этого компьютера".
3.2  Пункт [11] - установка apk, apks, apkm и xapk-файлов на устройство, управление установленными приложениями.
3.3  Пункт [12] - управление устройством через scrcpy (требуется android 5.0 или выше).
3.4  Пункт [13] - обмен файлами между устройством и компьютером, управление файлами на устройстве.
3.6  Пункт [14] - сохранение снимка экрана в папке проекта (требуется android 4.0 или выше).
3.7  Пункт [15] - запись видео с экрана и сохранение его в папку проекта (требуется android 4.4 или выше).
3.8  Пункт [16] - терминал устройства.
3.9  Пункт [17] - вывод важнейших системных логов logcat (в т.ч. radio, events, now) и bugreport, и сохранение их в файл в папке проекта.
3.10 Пункт [18] - различные варианты перезагрузки.
3.11 Пункт [19] - краткая информация об устройстве, монитор процессов htop.
3.12 Пункт [20] - корректно завершает работу сервера ADB.

5.   Настройки:
5.1  Пункт меню [80] позволяет переключаться между проектами. Название проекта соответствует имени папки, в которой будет вестись работа. Название проекта по умолчанию - ".", это соответствует корневой папке утилиты.
5.2  Пункты меню [81] и [82] позволяют выбрать для обработки один файл из папок _INPUT_APK и _INPUT_JAR соответственно. По умолчанию выбраны все файлы "*".
5.3  Если одна версия apktool сообщает об ошибке при декомпиляции или рекомпиляции, попробуйте другую версию (пункт меню [85]). В папку bin можно добавить любую версию apktool и smali, они должны иметь названия apktool_%номер_версии%.jar, smali-%номер_версии%.jar и baksmali-%номер_версии%.jar.
5.4  Опция [86] устанавливает режим обработки проблемных ресурсов. Подробнее здесь https://github.com/iBotPeaches/Apktool/pull/4044
5.5  При декомпиляции со включенной опцией [87] из смали-кода будет удалена отладочная информация (.local, .param, .line, и т.д.). Благодаря этому сравнивать смали-файлы между собой становится удобнее (например, от разных версий одного и того же приложения).
5.6  Пункт меню [89] позволяет выбрать ключ для подписи APK, ZIP, и JAR файлов. Вы можете добавить собственные ключи в папку bin, они должны иметь название %имя ключа%.pk8 и %имя ключа%.x509.pem
5.7  Сменить язык интерфейса утилиты можно, выбрав пункт меню [90]. Если вы хотите добавить перевод на ваш язык в дистрибутив утилиты, пишите в тему утилиты на форуме 4PDA: https://4pda.to/forum/index.php?showtopic=557858

6.   Расширенные настройки (пункт меню [00]):
6.1  Опция [1] позволяет сохранить оригинальный AndroidManifest.xml при рекомпиляции приложений. Подробнее здесь https://4pda.to/forum/index.php?showtopic=557858&view=findpost&p=54594895
6.2  При включении опции [2] при подписывании принудительно внедряется подпись v1 (JAR signing). Может пригодиться в некоторых специфических случаях.
6.3  При включении опции [3] при подписывании дополнительно будет сгенерирован файл подписи v4 (.idsig) рядом с результирующим файлом.
6.4  Опция [4] позволяет выбрать степень сжатия .dex-файлов при рекомпиляции файлов пунктами [06] и [08]. Степень сжатия 0 (по умолчанию) - наиболее совместимый вариант, 7 - оптимальное сжатие.
6.5  Пункт меню [5] позволяет выбрать версию AAPT, которая используется при рекомпиляции APK (только для apktool v2.4 - 2.12).
